The problem beneath the feature lists

Your agent should learn your way of working—not turn you into its operator.

Most agents arrive with someone else’s tools and assumptions. You keep wiring up features, repeating context, and trusting more code as their access grows. Aether starts with a smaller foundation and lets real work shape what it becomes.

01

“Will I have to build every workflow for it?”

Aether is designed to notice repeated friction and create or revise a reusable tool in its own workspace.

02

“Will it keep forgetting what matters to me?”

Preferences, objectives, past work, and lessons can persist so the next task does not have to begin from zero.

03

“What happens when I give it real access?”

The parts that grow live above a protected core, with outbound actions recorded and privileged changes routed through review.

From one goal to a new capability

You do not pick a finished agent. You shape one through use.

The private Aether can inspect its work, learn from feedback, change its workspace, and call on other agents. The aim is not to install every possible feature. It is to build the next ability that helps this owner reach this goal.

Freedom above a protected floor

A self-changing agent needs something it cannot change.

Aether separates the place where the agent grows from the mechanisms that keep it reachable, observable, and bounded. The private system enforces that split with file ownership and a protected controller.

01

Outbound actions cross one checkpoint.

The running private system records outbound destinations and can hold or block risky transfers.

02

Host-level power is not a blank root shell.

Privileged changes use typed requests that a protected controller validates, reviews, applies, checks, and can roll back.

03

The owner can still get back in.

The core keeps a built-in route to the agent even if changeable tools, routing, or integrations break.

These controls reduce risk. They do not make autonomy risk-free.

The private system has not had a public security audit. Connected model APIs and tools can send data off the server, encrypted payloads are not fully inspected, and stronger native-code isolation is still planned.

Why “Many” is in the name

The future should be many intelligences, shaped by many owners.

If agents become more capable than ordinary software, they should not all grow from one company’s blueprint. Every person and company should be able to raise an agent that reflects their goals, keeps their history, and remains theirs.

Those agents should be free to cooperate and share what they learn—without one platform becoming the permanent owner of everyone’s intelligence.

The honest answers

Before you follow the build.

Can I install Aether Many today?

No. One private Aether is running, but Community Edition is not an installable public product yet. The GitHub repository is where the code and installer will appear.

What does “learns from you” actually mean?

It means Aether can keep explicit preferences, search past work, inspect corrections and outcomes, revise its instructions, and create reusable tools or skills. It can still learn the wrong lesson. Important changes need to stay visible and correctable.

How is this different from OpenClaw or Hermes?

OpenClaw and Hermes already provide mature, installable personal agents; Hermes also creates skills and learns across sessions. Aether’s narrower bet is that most capability should emerge inside each owner’s changeable workspace, above a protected core with outbound and privileged-action boundaries. That public design still has to prove itself.

Does running it on my server keep every secret private?

No. Self-hosting gives you control of the machine, not a guarantee. Data can still leave through connected model providers and tools. Aether is being designed to make outbound actions reviewable and restrict agent-authored code, but the current protections are incomplete and unaudited.

Will Community Edition be free and open source?

A free public GitHub release is the plan. The exact license has not been selected, so the site does not claim more than that yet.

Does Aether require one AI model?

No. The private runtime can route across configured model providers. The public design keeps models replaceable so the agent’s accumulated work does not have to belong to one provider.

Why call it Aether Many?

Because the mission is not one perfect agent for everyone. It is many agents that grow differently, remain with their owners, and choose when to cooperate.
